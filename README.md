# AI 判分系统

老师出题并写好评分标准 → 学生提交答案 → AI 按标准逐条判分并给出理由 → 老师改分确认。
纯 Node.js 实现，**零第三方依赖**，可整体复制到任何电脑运行。

## 一、在另一台电脑上运行

1. 装 Node.js：到 <https://nodejs.org/> 下载安装 **18 或更高版本**（装 LTS 版即可）。
2. 把整个 `ai-grader` 文件夹复制过去。
3. 启动：
   - Windows：双击 `start.bat`
   - macOS / Linux：终端里执行 `./start.sh`（首次可能需要 `chmod +x start.sh`）
   - 或者命令行：`npm start`（等价于 `node server.js`）
4. 浏览器打开终端里提示的地址，默认 <http://127.0.0.1:3210>。

命令行可用的启动参数：

| 变量 | 作用 | 示例 |
|---|---|---|
| `PORT` | 指定端口，默认 3210；被占用会自动顺延到 3211、3212… | `PORT=8080 node server.js` |
| `HOST` | 默认 `0.0.0.0`，局域网内其他电脑/手机可访问；设为 `127.0.0.1` 则仅本机 | `HOST=127.0.0.1 node server.js` |

脚本也支持：`start.bat local` / `./start.sh local` = 仅本机访问。

## 一（补）、让其他电脑/手机用浏览器访问

服务默认已对局域网开放。启动后终端会打印类似：

```
 本机访问:     http://127.0.0.1:3210
 其他电脑访问: 用下面任意一个地址（同一局域网/WiFi 内即可）
               http://192.168.1.23:3210
```

把 `http://192.168.1.23:3210` 发给同一 WiFi 下的学生，他们用电脑或手机浏览器打开就能提交答案；
老师在任意一台电脑上判分、确认，所有人看到的是同一份数据（数据存在运行服务的那台机器上）。

页面右上角「设置 → 其他电脑访问」里也能直接看到这些地址并一键复制。

打不开时的排查顺序：

1. 两台设备是否连的同一个 WiFi / 局域网（手机流量不行）。
2. **Windows 防火墙**：首次启动会弹窗询问，务必勾选「专用网络」并点「允许访问」。
   没弹窗或误点了取消，可用管理员身份执行：
   `netsh advfirewall firewall add rule name="AI判分系统" dir=in action=allow protocol=TCP localport=3210`
3. 学校/公司的 WiFi 常开启「客户端隔离」，此时设备之间互相不可见 —— 换成手机热点或家里网络即可。
4. 运行服务的电脑不能休眠，服务窗口不能关闭。

> 注意：这是教学演示用的简易系统，登录为**页面级账号校验**（账号即密码），
> 能打开地址的人只要知道教师账号就能进入教师端。教师账户之间数据互相隔离，但请勿公开传播链接。

## 二、配置 AI 服务（必做，否则无法判分）

系统支持**任何 OpenAI 兼容接口**，三种配置方式，优先级从高到低：

1. **网页设置页（推荐）**：打开页面右上角「设置」，从预设里选服务商 → 填 API Key 和模型 → 点「测试连接」→「保存设置」。
   配置保存在本机 `data/settings.json`，不会上传。
2. **环境变量**：`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`（也兼容 `OPENAI_BASE_URL` / `OPENAI_API_KEY` / `OPENAI_MODEL`）。
   例：`AI_BASE_URL=https://api.deepseek.com/v1 AI_API_KEY=sk-xxx AI_MODEL=deepseek-chat node server.js`
3. **本机 WorkBuddy 网关**：如果在 WorkBuddy 环境里运行，会自动检测到并直接使用，无需任何配置。

内置预设：DeepSeek、通义千问、Kimi、智谱 GLM、硅基流动、OpenAI、本地 Ollama（无需联网也无需 Key）、自定义。
其他服务只要兼容 `/chat/completions` 协议，选「自定义」填地址和模型即可。

## 三、账号与登录（必须先登录）

打开页面先出现登录框，账号与密码规则如下，**每个账号的初始密码与账号相同**：

| 角色 | 账号范围 | 数量 | 可访问页面 |
|---|---|---|---|
| 教师 | `00000` – `00005` | 6 个 | 出题、判分与确认、判分对比、设置 |
| 学生 | `26006` – `26200` | 195 个 | 仅学生端（提交答案、查看自己的成绩） |

- 例如教师账号 `00003`，密码 `00003`；学生账号 `26006`，密码 `26006`。
- 不在上述范围内的账号无法登录；密码与账号不一致会提示「密码错误」。
- 登录后 12 小时内免重复登录；右上角「退出」可清除登录状态。
- **教师账户彼此独立**：每个教师账号只看到、也只能操作**自己发布的题目**及其下的判分记录；
  看不到其他教师的题目、提交和分数，也不能删除或改分（接口层会返回 403）。
  历史数据（升级前发布的题目）统一归属 `00000`。
- 学生端能看到全部题目（用于选择作答），但只能看到**自己账号名下**的提交与成绩。
  选择题目前先选「教师」，再只列出该教师发布的题目。
- 提交记录（含 AI 分、老师终评）在实际出题的那个教师的账号下。
- 页面上的账号校验 + 服务端 `X-Account` 归属校验双重拦截；云端数据库当前为「应用内公开读写」策略，
  因此隔离由应用层保证。若用于正式场景，请自行更换密码策略并考虑接入真实登录鉴权
  （修改 `public/index.html` 中的 `AUTH` 规则与 `server.js` 顶部的 `AUTH` 常量）。

## 四、使用流程

- **出题**：填写题目标题、题目内容、评分标准（每行一条，建议标注分值）、满分 → 发布。
- **学生端**：先选教师 → 再选该教师发布的题目 → 填姓名、提交答案 → 立即显示 AI 分数和逐条理由（此时状态为「待老师确认」）。
- **判分与确认**：选题目 → 查看每份答案的 AI 分数、逐条评分理由、判分用时 → 可直接改分并写评语 → 点「确认成绩」。
  也可以点「重新 AI 判分」再跑一次。
- **判分对比**：统计 AI 分与老师终评分的差值、AI 平均判分用时。

## 五、数据存放

两种模式，靠 `data/cloud.json` 是否存在切换：

**① 云端模式（当前默认，本机与线上共用同一份数据）**

存在 `data/cloud.json` 时，本机服务不再写本地 JSON，而是直接读写云数据库：

```json
{ "endpoint": "https://<你的应用域名>",
  "publishableKey": "<云服务下发的 publishableKey>" }
```

配置来源优先级：环境变量 `CLOUD_ENDPOINT` / `CLOUD_PUBLISHABLE_KEY` → `data/cloud.json`。
`data/cloud.json` 已在 `.gitignore` 中，不会进仓库；需要时可以复制 `data/cloud.example.json` 起手。
前端拿到的配置由服务端在 `/cloud-config.js` 里按请求动态生成，代码里没有任何密钥字面量。

- 本机（localhost / 局域网）出题、提交、判分、改分 → 实时写入云端，线上刷新即可看到
- 线上改动 → 本机刷新也能看到，两端始终一份数据
- AI 判分仍由**运行服务的这台电脑**调用模型（线上沙箱访问不到本机模型网关），判分结果写回云端
- 启动日志会打印「数据存储: 云端数据库」；「设置 → 其他电脑访问」也会显示当前存储模式

**② 本机模式（默认旧行为）**

删掉 `data/cloud.json` 即可退回：

- `data/db.json`：题目、学生提交、AI 判分结果、老师确认结果
- `data/settings.json`：AI 服务配置（含 API Key，注意不要外传该文件）
- 与线上数据**互相独立**，改动不会同步

## 六、密钥与仓库安全

- **代码里没有任何密钥字面量**：大模型 API Key 由教师在「设置」页填写，保存在服务端的
  `data/settings.json`（本机模式）或云端设置里，不写进任何源码文件；也可以用环境变量
  `AI_API_KEY` / `AI_BASE_URL` / `AI_MODEL` 注入。
- 云服务的 `publishableKey` 只是「公开标识键」（云端按来源域名识别应用），同样通过环境变量或
  `data/cloud.json` 注入，两个文件都已被 `.gitignore` 排除。
- 以下运行期文件不会提交到仓库：`data/db.json`（含学生答案与批改记录）、`data/settings.json`、
  `data/cloud.json`、`.env*`、`node_modules/`、`.tmp/`。

## 七、实测脚本（可选）

服务启动后，在 `ai-grader` 目录执行 `node test/run-test.js`，会自动发布一道题、提交 5 份不同质量的答案、
跑 AI 判分并与人工评分对比，结果写入 `test/评测报告.md`。
若服务不在默认端口，用 `BASE=http://127.0.0.1:3211 node test/run-test.js` 指定。

## 八、公网访问（广域网，跨网络也能用）

局域网方式要求大家连同一个 WiFi；要让**任何网络**下的电脑、手机都能打开，需要把服务发布到公网。

本项目已发布为在线应用：**https://ai-grader-98109.app.workbuddy.host/**

发布后的注意事项：

1. **必须重新配置一次 AI 服务**。本机运行时用的是 WorkBuddy 本机模型网关（地址是 127.0.0.1），
   云端实例访问不到它。打开公网链接 → 「设置」→ 选服务商 → 填你自己的 API Key → 测试连接 → 保存。
   配置只保存在云端实例里，不和本机共享。
2. **数据是两份**：本机 `data/db.json` 和云端实例各存一份，互不同步。
   重新发布会用本机的 `data/db.json` 覆盖云端数据 —— 正式使用时请固定用公网版，别反复发布。
3. **登录是「页面级」隔离**：账号规则 教师 00000–00005 / 学生 26006–26200，密码与账号相同，
   当前身份由前端登录后通过 `X-Account` 请求头带给服务端。服务端会校验归属（越权改分/删题返回 403），
   但请求头本身可被伪造，**不适合当正式考试的防作弊系统**；如需生产级安全，应换成服务端签发
   Session/JWT 并强制校验密码。

如果不想申请 API Key，也可以在本地机器上运行服务并用内网穿透工具（frp / cloudflared 等）暴露到公网，
这样 AI 仍走本机网关、数据也留在本地，只是需要自己准备穿透工具和一个公网服务器。
